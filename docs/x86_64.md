# Waydroid x86_64 控制端（v0.5.0 实验版）

此版本实现了 x86_64 原生加载与控制代码。游戏仍使用 arm64 libil2cpp，
因此功能执行端仍是 arm64；它不是把游戏重编译成 x86_64。

## 调用链

1. Kotlin 根据内核架构和进程位数选择 x86_64 路线，只在游戏主进程工作。
2. 从 APK 解出 `lib/x86_64/libakl_core.so`，由模块的 NativeBridge 加载。
3. 解出 `assets/akl/libakl_guest.so`。它不放在安装包的 arm64 JNI 目录中，
   所以专用包的安装 ABI 可以保持 x86_64。
4. x86_64 控制端动态解析平台导出，取得游戏 ClassLoader 的原生命名空间，
   用 `OpenNativeLibraryInNamespace` 加载 guest，并检查 `needs_native_bridge` 为真。
5. 通过 `NativeBridgeGetTrampoline` 取得 JNI 签名为 `I` 的探针，实际调用并校验协议标记。
6. 实验版默认在探针通过后返回状态 2。显式启动引擎时，取得签名为 `IIII` 的功能入口跳板，传入配置并读取结果。
   不直接把 arm64 地址当 x86_64 函数调用，不运行 guest 的 JNI_OnLoad，
   避免覆盖 x86_64 控制端注册的 JNI 方法。

guest 运行后会等待 il2cpp、附加 il2cpp 线程、尝试安装所选 hook。
返回 0 表示至少一个 hook 安装成功；返回 1 表示仅启动异步工作线程，
尚未确认功能成功。即便安装了 hook，仍需在战斗中确认效果。
已调用过的 guest 不会重复启动，避免安装重复 hook；更改配置后须重启游戏。

## 构建

`bash scripts/build-native.sh` 生成 host、guest 和 guest 资产，可用于构建 universal 包。
专用 x86_64 包执行 `bash scripts/build-waydroid.sh`，输出到 `build/zoot-waydroid-x64.apk`。
脚本在临时副本内裁剪 ABI，完成后不改变源码目录的原生库。
不能只给 `flutter build` 传 x64 参数却保留其它 ABI 的预编译 JNI 库。

产物 `zoot-waydroid-x64.apk` 应包含：

- `lib/x86_64/libakl_core.so`：x86_64 host
- x86_64 Flutter 库
- `assets/akl/libakl_guest.so`：arm64 guest

不能用旧 v0.4.0 APK 测试本路线。该 Release 不包含新控制端。

## 日志与错误

`AKL-X64` 是 host 日志；`AKL` 中的 `AKL-GUEST` 标记是 guest 的真实入口日志。

| 状态 | 含义 |
| --- | --- |
| 2 | arm64 探针通过，本次未启动功能引擎 |
| -30 | 平台接口不可访问，或 NativeBridge 未初始化 |
| -31 | 找不到游戏原生命名空间 |
| -32 | guest 加载失败，详见该条日志中的平台错误 |
| -33 | 平台返回了非翻译库句柄，不继续调用 |
| -34 | 探针跳板缺失，或返回的协议标记不对 |
| -35 | 功能入口跳板缺失 |
| -36 | guest 文件不是 arm64 ELF |
| -10…-15 | 已进入 guest，但引擎架构、il2cpp、线程或 hook 初始化失败 |

平台 API 是 Android 的内部接口，并不属于 NDK 的稳定 API。
本机系统镜像确认它们导出，但模块命名空间禁止直接访问它们。
解析器排除会自递归的 `_lazy.so` 转发库；常规符号解析失败后，
从已加载的 ART ELF 查找导出函数。它检查映射路径、文件身份（APEX
设备号不同时核对 GNU build-id）、ELF 边界、导出类型和可执行地址范围。
失败时记录阶段并停止；不猜测私有结构布局，不调用未经转换的 guest 指针。

接口依据：

- [AOSP native_loader.h](https://android.googlesource.com/platform/art/%2B/9b16e344b246096d228dd4b41ff711884bcfcb3e/libnativeloader/include/nativeloader/native_loader.h)
- [AOSP native_bridge.h](https://android.googlesource.com/platform/art/%2B/c8d6e3b523f31baa548934f822c6e36adc2a52e8/libnativebridge/include/nativebridge/native_bridge.h)

## 实机验证（2026-10-22）

设备：Waydroid / Android 13 / x86_64 / Houdini 14.0.0，
LSPosed 1.9.2，官服明日方舟 2.7.81。已构建并安装 v0.5.0，安装 ABI 为 x86_64。

已验证：真实 ART 平台接口解析成功、游戏原生命名空间加载 arm64 guest 成功、
跨架构探针实际执行并返回正确协议值。PID 6406 在 06:05:15 完成探针，
到 06:08 仍存活。关键日志：

```text
AKL: AKL-GUEST: arm64 探针已执行
AKL-X64: stage=guest-probe status=2: arm64 probe passed; feature engine was not started
```

5 秒默认延迟下，过早调用 `il2cpp_domain_get` 出现 SIGSEGV。
修正配置读取、实际等待 30 秒后，PID 7161 的完整入口成功读取 domain、
附加 il2cpp 线程、按名称找到 `UnityEngine.Time`，并返回到 x64 宿主；
游戏保持运行并到达标题画面。这支持“早期调用时序有问题”的判断，
但固定延迟不是运行时已初始化的可靠证明。

当前倍速 hook 的目标序言含 PC 相对指令 `0x9001b8d3`，现有保守 hook 实现
主动拒绝安装，返回 -15（0 个 hook）。没有确认任何战斗功能生效。

```text
AKL: il2cpp 线程附加成功，开始解析功能目标
AKL: 找到类 UnityEngine::Time
AKL: 序言含 PC 相对指令 0x9001b8d3，放弃 hook
AKL-X64: stage=guest-return status=-15
```
默认仅执行探针，系统属性未设置时也如此；仅在明确进行引擎诊断时：

```sh
adb shell su -c 'setprop debug.akl.probe_only 0'
# 冷启动游戏并收集 AKL / AKL-X64 / Houdini 日志
# 恢复探针模式后重新启动游戏：
adb shell su -c 'setprop debug.akl.probe_only 1'
```

另修复 LSPosed 1.9.x 共享配置权限：应用按 [LSPosed 文档](https://github.com/LSPosed/LSPosed/wiki/New-XSharedPreferences/50ba6cc90a70068f4778264bd22c2b836121a5a1)
尝试以 MODE_WORLD_READABLE 打开配置，未激活框架时回退私有配置。此前界面的 30 秒延迟实际未被游戏读取，
chmod 后实测加载线程按 30 秒启动。每次启动记录实际配置，避免混淆默认值。

host / guest 交叉编译、完整 APK 构建、模拟平台错误处理与并发保护、
实际 ELF 导出解析测试均已通过。ASan / UBSan / LeakSanitizer 在全权限环境通过，
不再需要沙箱下的禁用泄漏检查选项。战斗效果仍未验证。
